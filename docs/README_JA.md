# 日本語概要

論文の補助資料・公開用に、次の3条件の実装と全126ケースの記録を整理したものです。

| 条件 | 公式採点合格数 | 合格率 |
|---|---:|---:|
| 一発生成 | 74/126 | 58.7% |
| 独立したフィードバック修正 | 99/126 | 78.6% |
| SDK間コード共有＋自身の診断保持＋停滞時の文脈マスキング | 108/126 | 85.7% |
| SDK間共有なし・停滞時再検討あり（2回） | 103/126、103/126 | 81.7%、81.7% |
| SDK間共有なし・停滞時再検討なし（1回） | 102/126 | 81.0% |

追加した2行は同じ初期候補からの補足実験です。反復数が異なり、1件の差から
停滞時再検討の優位性は確定できません。[条件・記録](ablation/NO_PEER_RESTART_COMPARISON.md)。

モデルはGPT-6 Astra、medium。修正は最大5回です。他SDKの診断は共有しませんが、
生成コード・出力・合否は共有します。直近2回の実行が不合格で出力のL1距離が0.02以下なら、
その修正の入力から自身の過去コードと診断を伏せます。追加のLLM呼び出しや評価はありません。

**108は開発中の1系列の実測です。停滞対策が改善の原因と確認されたわけではありません。**
同じ設定で修正を再生成した実験では107件でした。公式合格が仕様上の正しさを保証しない
例もあるため、詳細は [結果と限界](RESULTS.md) に記載しています。

追加実験として、他SDKのコードだけを隠す条件と、問題文・コード・合否・出力・
エラー・過去履歴をすべて隠す条件を各2回評価しました。コード非表示条件は107・107件、
全情報非表示条件は103・103件でした。比較条件（コード以外の情報あり）は106・107件です。
平均差は示唆的ですが、信頼区間はゼロを含むため、安定した優位性とは断定していません。
詳細は [追加アブレーション](ablation/NO_PEER_RESULTS.md) と
[コード共有の切り分け](ablation/PEER_CODE_ABLATION_RESULTS.md) を参照してください。

まず `python3 scripts/audit_results.py` で合格数を再集計できます。LLMは呼び出しません。
保存コードの再採点と、新しいLLM生成は別コマンドです。[README](../README.md) を参照してください。

このディレクトリだけを独立したリポジトリとして使用できます。実験用リポジトリへの
実行時依存はありません。依存ライブラリと上流ベンチマークは別途セットアップします。
